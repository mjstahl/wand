# Signatures the fuzzer has found and that are not yet fixed. One per line,
# with a comment saying what it is. A line here keeps a nightly run green
# for a bug already written down -- it does not hide it: the summary counts
# every hit under "known, not failing".
#
# A line leaves when the bug is fixed. Where the fix goes depends on the
# finding. One that can be written as an ordinary test belongs in the
# ordinary suite. One that cannot, because the input is a byte sequence no
# person would write, goes into test/fuzz/regressions/ as the input itself.
#
# The reproducer is written out beside each line here, because these are
# small enough to read and a signature on its own is not something anyone
# can act on.

# ── The formatter writes source that does not parse ──────────────────────
#
# A `;`-separated block whose second statement is a `let`, printed on one
# line after a URL literal:
#
#   (http://; let s = (fn -> r) [] [] in ())
#
# comes back "expected ), got let". `fuzz --seed 1` finds it. Not
# minimised.
format:unparses

# ── The formatter takes a raw string apart ───────────────────────────────
#
# Nine bytes:
#
#   ``!`t
#   `!e
#
# comes back with the backticked pieces on lines of their own, and a raw
# string is its layout -- the text between the backticks is the value, so a
# newline written into one is a newline in the value. Reported as
# `format:unstable` because the second pass moves them again.
format:unstable

# ── The formatter is exponential in nesting depth ────────────────────────
#
# Recorded first as a nine-second typecheck, which it is not. The typecheck
# takes 0.01s. `fuzz --input` runs the formatter oracle as well, and that is
# where the time goes: 5.57s to format the 7.4KB input at a 79-column
# margin.
#
# It doubles with every level of nesting. `f (f (f ... x) 1) 1`, formatted
# at a 40-column margin:
#
#   depth 16    0.04 s
#   depth 20    0.83 s
#   depth 22    4.13 s
#
# The margin is what decides whether it bites. The same depth-22 expression
# takes 0.01s at 92 columns and 4.03s at 40: the blow-up needs a run of
# levels that each fail to fit, because each level renders its subtree once
# to ask whether the one-line form fits and again to write the wrapped one.
# That is why the corpus is fast at the default margin and why the fuzzer,
# which draws a margin per input between 24 and 119, keeps finding it.
#
# Fixing it means the emitter stops rendering a subtree twice -- memoising
# on the node, or measuring width without building the string. Both are more
# than a patch.
timeout
